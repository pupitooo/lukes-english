# Working on Luke’s English

Petr’s English study space, published with GitHub Pages: https://pupitooo.github.io/lukes-english/. Static site built by `python3 scripts/build.py` (standard library only) into `_site/`. Every push to `main` builds and deploys it. See `README.md` for the content layout and `npm test` for the browser checks.

## Where new material goes

Decide first where the material comes from. Both sources must end up in the library.

1. **Lessons from Luke** (usually arrive by e-mail in Petr’s Proton mailbox): `content/lessons/YYYY-MM-DD/` with a `meta.json` (title, description, date, sequential `number`, tags). Keep original file names and attachments together. They show up under *Lessons with Luke*.
2. **Petr’s own additions from conversations with Claude** (his texts, corrections, retold versions, extra phrases): they belong under *My topics*.
   - Stories → `content/stories/<slug>.json` (format below). They render into the **My stories** card.
   - Tests and exercises → `content/topics/<topic>/` like the existing ones.

Never create a standalone page outside the library. Everything has to be reachable from the main page through the catalog (`assets/catalog.json` is generated by the build).

## Story files

`content/stories/<slug>.json`:

- `title`, `description`, `date` (ISO), `order`, `original` (Petr’s text, verbatim, typos included, shown only on request).
- `versions`: usually three, each `{ "tense", "corrected", "en", "cz" }`. `tense` is `past`, `news` or `period` (explanations are in `scripts/stories.py`). Only the first version is `corrected: true`; the others are the same story retold: *just happened* (present perfect, starts “You won’t believe what has happened”) and *“I’ve had a crazy week”* (present perfect for an unfinished period). Every version needs a Czech translation in `cz`.
- `changes`: lists of “Tenses” and “Words and phrases” notes that explain the corrections.
- Markup in `en`: `{old|new}` correction, `{|new}` insertion, `{old|}` deletion, `[[text]]` highlights a tense form.
- Correct the tenses and the wrongly used words; do not mark plain typos in the explanations.

## Keep it consistent with every push

- Run `python3 scripts/build.py`; it validates links and must succeed.
- A new lesson, topic or story must appear in the library; update the counts and descriptions in `README.md` if they change.
- New sentences Petr wants to practise also go into Anki (AnkiWeb, deck `Petr::English::Aktuální`, note type `Petr English v1`): Czech in *Prompt*, English in *Answer*, `ID` like `story-<slug>-NN`, `Source` “Story: <slug>”, tag `story-<slug>`. Search for duplicates first and add nothing twice.
- Open the built page in the browser pane when the UI changed.

## Git

- Commit as `pupitooo <pupe.dupe@gmail.com>` (already set in this repo’s local config). No `Co-Authored-By` or other signature lines, by Petr’s request.
- Push with a plain `git push`. The remote is SSH and a repo-local `core.sshCommand` loads a deploy key from 1Password (`op` CLI), so the machine’s default GitHub login (a work account) stays untouched. Never change global git, ssh or 1Password settings for this repo.
- Do not commit `_site/`, `node_modules/` or `.apkg` files.
